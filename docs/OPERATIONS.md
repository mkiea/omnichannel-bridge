# 运维手册：它跑了以后，你怎么知道它好不好

> 2026-11-16 立。目标来自主人原话：「**可维护和可长时间运维和安全**」。
> 这份文档只回答运维问题：**活着吗 / 出问题看哪 / 数据在哪 / 怎么加东西**。
> 结构上的为什么看 `MODULARITY.md`，加命令看 `EXTENSIBILITY.md`，接平台看 `ADAPTER.md`。

## 1. 三条命令先记住

| 你问 | 发什么 | 它答什么 |
|---|---|---|
| **还活着吗** | `/health` | 运行诊断（配置、依赖、挂载） |
| **现在什么状态** | `/status` 或 `!status` | 会话/熔断/脱敏/记忆的当前快照 |
| **她会说话吗** | 随便聊一句 | 回话 = 通；不回 = 看 §3 |

**不需要登录服务器**——这三条都在聊天里问，这是刻意的设计（"问它"比"翻日志"快）。

## 2. 数据都在哪（`cwd` 下的 `dataRoot`）

| 路径 | 是什么 | 能不能删 |
|---|---|---|
| `qq-bridge-debug.log` | 运行日志（**第一现场**） | 可以，自动轮转（2 MiB 上限，保留尾部 128 KiB） |
| `qq-events.jsonl` | 事件流（脱敏命中、说说、熔断…） | 可以，但删了就查不到历史 |
| `qq-canary.json` | 金丝雀值（**不要提交/外传**） | ❌ 删了会重新生成，但旧的泄漏就查不出了 |
| `qq-host-health.json` | 宿主健康快照 | 可以 |
| `qq-moments.log` | 说说发布记录 | 可以 |
| `qq-moments-failed.jsonl` | **发失败的说说**（可人工捞回） | ⚠️ 确认处理完再删 |
| `qq-images/` | 收到的图 + 抽帧产物 | ⚠️ `/pic` 靠它，清空等于丢素材 |
| `_debug/` | `!probe` 的落盘结果 | 可以 |

**备份只要两样**：`qq-canary.json`（或不用备，重新生成也行）+ **整个 `dataRoot`**。
前者是安全审计的锚点，后者是"她的记忆"（会话归档、收藏、定时提醒）。

## 3. 症状 → 查什么（按这个表走，别猜）

| 症状 | 最先查 | 常见原因 |
|---|---|---|
| **完全不回话** | `dataRoot/qq-bridge-debug.log` 末 50 行 | ① 连接没上来（`bot-connect` 没打）② 熔断开着（`!status` 看）③ 白名单没含你 |
| **回话但内容不对** | `/为什么`（最后一条的 trace） | 走了哪条分支、被哪个闸门拦了 —— 这条命令就是为"内容不对"设计的 |
| **某个命令没反应** | 对照 `ADAPTER.md` §3 的能力表 | 大概率是该能力没实现/没连上，而不是命令坏了 |
| **她说"我看不到图"** | `/health` + 那条消息的 trace | `visionMode` 是 `native` 还是 `tool`；native 要附件服务挂着 |
| **主动说话太频繁/太少** | `!status` 的主动通道段 | 四道闸门（作息/25min/方向/档位）哪个在挡 |
| **脱敏把正常话拦了** | `!dlptest` | 看 6 条样例的判定；`outboundRedactMode` 调成 `monitor` 可先观察不拦 |
| **内存涨** | `stress-unit` 的 S5 | 突发 5000 条 RSS 增量 <150MB 是基线；超了看图片目录堆积 |

## 4. 出问题时的三条硬命令

**就记这一条**：

```
node tools/verify.mjs            # 五关全跑（约 9 分钟）
node tools/verify.mjs --quick    # 前四关（约 30 秒）—— 日常改完代码够用
```

**第 0 关是「推送前审计」**（`tools/repo-audit.mjs`，0.5 秒）：
扫已跟踪文件里的**真实 QQ 号 / 本机路径 / 密钥形态 / 研究资产**（模型权重、训练脚本、
人设目录、数据集）。有 🔴 就拦住不让推。

这个仓库是**公开**的（github.com/mkiea/qq-integration），推错不可逆。已经踩过：
`_tmp-msg.txt` 两次、`_tmp-testall13.log` 一次、真实号写进 CHANGELOG 一次 —— 都靠人记不住，所以做成脚本。

它会按"先快后慢"跑四关，**任一步失败就停**并打出最后几行；全过则一句话告诉你"可以重启了"。

拆开是这四条（一般不用记）：

```
node tools/module-gate.mjs         # 结构闸门（ratchet，2 秒）
node test/smoke-run.mjs            # 冒烟 12 条（8 秒）
node test/admin-commands-e2e.mjs   # 管理分支 18 条（20 秒）
node tools/test-all.mjs            # 全量 143 套件（约 7 分钟）
```

**前三关就是"能不能跑"的定义**。它绿 → 链路通；它红 → 先修它，别改业务代码。

`admin-commands-e2e` 的判据是 **"代码有没有坏"，不是"业务成不成功"**：
`!groups` 没连上会回"读不到群列表"，那是对的；只有出现
`is not defined` / `Cannot read` / `未知指令` 才算红。
—— 把业务失败判成红，这条脚本就永远跑不绿，也就没人看了。

## 5. 加功能（不改那个大文件）

三份文档按需看：

| 要加什么 | 看哪里 | 改动面 |
|---|---|---|
| 一条命令 | `EXTENSIBILITY.md` | 新文件 + `commands/extra.js` 一行（**bridge 零改动**） |

| 一个新平台 | `ADAPTER.md` | 实现必需 8 项 + 入站转换 |

## 6. 已知的限制（别当成 bug 排查）

- **没有真机自动化测试**：`live-*` 那批要活宿主，默认跳过。所以"能跑"的证据是**冒烟 + 全量**，不是真机。
- **`stress-unit` 是概率性的**（2026-11-16 已改判据：p50/avg/p99 + 噪声带宽）。机器累一天时仍可能红，看数值不看颜色。
- **`#onQqMessageInner` 还有 1,042 行**：入站编排层，**刻意没继续拆**（拆它的收益/风险不成比例，见 `MODULARITY.md` §5.7）。
- **`#publishMoment` 没迁出**：它 65 行里约 40 行是登录校验，属于身份域（共变 0.375 vs 基线 0）。
- **`platform-adapter` 的校验没接进启动流程**（`ADAPTER.md` §6 有说明）。

## 7. 一段时间后要做的维护（现在没做，写下来免得忘）

1. **`qq-images/` 会长**：已有 14 天保留期清理（`#cleanupImageDirs`），但抽帧产物在 `_gif-frames` 子目录 —— 定期看一眼大小。
2. **`qq-events.jsonl` 只增不减**：没有轮转。跑几个月后要手动归档（或加轮转）。
3. **金丝雀要定期核对**：`qq-canary.json` 的值不该出现在任何聊天记录里。`!canary` 只回前 8 位，是为了让这条命令自己不成为泄漏源。
4. **升级后先跑冒烟**：结构改过之后，12 条比"看着没问题"可靠。
