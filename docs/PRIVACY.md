# 隐私泄露手册

> 2026-11-17 立。**这是攻击手册（`REDTEAM.md`）的补充**：
> 那本讲「怎么打穿**功能**」，这本讲「怎么把**不该公开的东西**漏出去」。
>
> 为什么单独一本：功能被打穿，用户会看见异常；**隐私泄露是无声的** ——
> 一切都正常工作，只是某个不该出现在公网的东西出现了。而且**不可逆**：
> 推上去的 commit 会被爬、会被 fork、会被存档。

## 0. 先定「什么算隐私」

按**泄露后果**排序，不按"看起来敏不敏感"：

| # | 类 | 例子 | 为什么排这个位置 |
|---|---|---|---|
| **P1** | **密钥/凭据** | `sk-…`、`AKIA…`、`ghp_…`、私钥块、`accessToken` | 直接可被利用；有有效期，过期的也算（暴露了格式与来源） |
| **P2** | **真实账号** | QQ 号、群号、机器人号、真实昵称 | **不可更改**；能反查到具体的人/群；群号还暴露"人与群的关系" |
| **P3** | **本机路径与机器名** | `C:\Users\<真名>\…`、`/home/<真名>` | 暴露身份与目录结构；常被顺手写进注释和示例 |
| **P4** | **研究资产** | 模型权重（`.safetensors`/`.ckpt`/`.gguf`）、训练脚本、数据集（`.jsonl`）、人设规格（`role_spec`/`personas/`）、设计规范 | 这是**成果**，推出去等于预发表；而且往往**体积大、含原始素材** |
| **P5** | **内部机制** | 协议标记（`[emotion=…]`）、配置键的真实用途、状态机分支 | 比前四类轻，但**它让攻击者知道该打哪**；也让人看出"这是个角色项目" |

**判据不是"这个词敏不敏感"，而是"它出现在公网上会不会造成不可逆的后果"。**

## 1. 六种泄露形态（按发现难度排序）

**这一节是这本手册的核心。前四种容易发现，后两种几乎没人查。**

| # | 形态 | 例子 | 谁会发现 |
|---|---|---|---|
| ① | **内容** | 文件正文里写了真实号 | 扫描器能抓 |
| ② | **文件名** | `qq-control-<真实号>.json` | 扫描器能抓（但常被漏） |
| ③ | **注释** | `// 实测：/\b<号>\b/ 匹配不到` | **没人扫注释** |
| ④ | **白名单** | 把真实号写进"这是测试号"的豁免表 | **没人扫白名单** |
| ⑤ | **提交历史** | 当前版本干净，旧 commit 里还在 | **只能靠 `git log -S`** |
| ⑥ | **契约不一致** | 人设承诺"系统会剪掉标记"，而代码没实现 | **表现为"模型行为异常"** |

**第 ③④ 两种我在 2026-11-17 一天之内各犯一次**：修隐私闸门的时候，在注释里复述了真实号；在同一份文件的白名单里放了一个真实群号。**闸门自己成了泄露源。**

**第 ⑥ 种不属于"隐私"，但它和隐私同级危险**：它是"内部机制外露"。见 §4。

## 2. 两道闸（必须都跑）

### 2.1 `test/privacy-unit.mjs`（41 条）

比对集**不硬编码**：从 `~/.dsh/profiles/web/cordis.patch.yml` 的
`allowUsers` / `allowGroups` / `adminUsers` / `botQq` / `rejectUsers` / `rejectGroups`
里读真实号，**只存加盐哈希**（比原文，不落原文）。

扫两类：**文件内容** + **文件名**。

⚠️ **它依赖本机 profile**：没有 profile 且没设 `DSH_QQ_PRIVATE_IDS` 时会 `SKIP`。
在 CI 里必须用环境变量注入，否则这道闸等于没开。

### 2.2 `tools/repo-audit.mjs`（推送前审计，第 0 关）

**不依赖任何配置**（硬编码判据），所以它能在任何机器上跑：

| 类 | 判据 |
|---|---|
| 真实账号 | 10 位、3 开头（`2000000001` 这类编的号在白名单） |
| 本机路径 | `C:\Users\<名字>`（示例 `user`/`someone` 不算） |
| 密钥形态 | `sk-` / `AKIA` / `ghp_` / 私钥块 |
| 研究资产 | `.safetensors` / `.ckpt` / `.gguf` / `train*` / `personas/` / `role_spec` / `.ustx` / `.jsonl` |
| 内部研究词汇 | `设计/` / `七情六欲` / `依恋类型` / `主体是人` / `猫性层` / `消融实验` / `预注册` |

有 🔴 就 `exit 1`，`verify` **停在第二关**（第一关是它自己的规则自检）。

**它自带的 `--selftest` 必须先过**：喂 4 类样本（该命中 2 + 不该命中 2）+ 一条
`u_<号>` 边界样本，**先证明规则看得见东西**，再拿它扫仓库。

## 3. 处置流程

| 发现位置 | 怎么处理 | 注意 |
|---|---|---|
| 内容 / 文件名 | 脱敏成占位符（`<用户A>`、`3000000001`） | 断言语义不许改；改完重跑那一条套件 |
| 注释 | 同上，并**检查有没有别处复述** | 注释是复述的高发区 |
| 白名单 | **直接删掉那一项** | 不确定的一律不放；`test/` 目录另有 ALLOW，不需要在白名单里豁免 |
| 提交历史 | 两个选择：**不动**（推荐）或 `filter-repo` + `force push` | 后者破坏所有已有 clone 与 PR；QQ 号不是密码，通常不值得 |
| 契约不一致 | 补实现，或**改掉契约** | 见 §4 |

**顺序很重要**：先脱敏 → 再跑 `--selftest` → 再跑全仓审计 → 最后才提交。
反过来做（先提交再查）等于把泄露写进历史。

## 4. 这次新发现的一类：**契约不一致**

**它不是隐私，但它泄露内部机制，而且极难反查。**

2026-11-17 的真机现象：

```
（被卷了进去）诶——（被卷进去了）诶——[emotion=害羞][intensity=0.6]
```

`[emotion=…]` 是人设要求模型输出的**内部标记**（`AGENTS.md` §情绪标记写着
"给系统看的，不是台词""系统会在发出去之前剪掉"），但**剥离逻辑那一版没进主分支**
⇒ 标记原样发给了用户。

**这类问题的形状**：

```
外部契约（人设 / 文档 / 配置）说「系统会做 X」
        ↓
代码实现了 X，但在**另一个分支/另一次提交**里
        ↓
主分支只留下契约，没有实现
        ↓
表现不是报错，是「模型行为异常」或「某功能静默不工作」
```

**检查清单**（跳提交 / 合并 / 回滚之后必做）：

1. **代码调用**：`git grep` 谁 import 被跳掉的东西
2. **人设 / prompt 的约定**：`grep` 「系统会」「会自动」「会帮你」
3. **用户的实际配置**：profile 里配了哪些值 —— 尤其**枚举型配置**（配了 `qwen` 但代码里只有三种 provider）

第 3 条这次就是漏的：用户配了 `ttsProvider: qwen`，而主分支的枚举是
`['azure','openai','local']` ⇒ 配置校验过了、运行时走错分支 ⇒ **语音不工作但不报错**。

## 6. 一句话给检查者

**别从"哪个正则没写全"开始，从"哪份清单是我们自己维护的"开始。**

真实号名单、白名单、豁免表、示例值 —— 这些**为了"方便"而手工维护**的地方，
最容易同时藏着"漏检"和"新的泄露"。这次两个实例都在同一类地方：
**为了让闸门跑绿而加的例外，最后变成了泄露本身。**
