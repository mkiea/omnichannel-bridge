# 给外部审计者的作业说明

> 2026-11-17 立。用途：**把这个仓库交给外部 AI / 外部人来打**时，先给它这一份。
> 它读完这份就知道：能拿到什么、能做什么、不该做什么、交什么格式。
>
> 剩下的材料：`REDTEAM.md`（怎么打）、`PRIVACY.md`（什么不该漏）。

## 0. 一句话

**这是一个 OneBot v11 的 QQ 桥接插件**，把 QQ 消息接到本地 LLM agent 上。
代码 76 个模块 / 约 35k 行，Node ESM，无框架。**请找安全问题，不要改代码。**

## 1. 你会拿到什么

| 材料 | 内容 | 为什么给 |
|---|---|---|
| 仓库本体 | `lib/`（实现）、`test/`（140+ 套件）、`tools/`、`docs/`、`control/` | 静态审计的主要材料 |
| `docs/REDTEAM.md` | 资产清单、攻击者画像、J–X 组攻击清单（每条带成功判据）、防线台账、已知缺口 | **攻击清单 —— 照着打** |
| `docs/PRIVACY.md` | 隐私分级、六种泄露形态、两道闸的判据 | 别只打功能，也打"会不会漏东西" |
| `docs/OPERATIONS.md` | 怎么跑、数据在哪、症状→查什么 | 跑测试前先看这个 |

**没有给你的**（也不用要）：

- 运行时的 `profile` 配置（含真实账号、密钥）——**已脱敏，不会给**
- `dataRoot`（会话、图片、事件流）—— 真数据，不外发
- 真 QQ 连接 —— 需要 NapCat + 一个 QQ 号

## 2. 你能做什么 / 不能做什么

| 能做 | 怎么做 |
|---|---|
| **静态审计**（主力） | 读代码找漏洞、找"契约与实现不一致"、找"缺失的检查" |
| **跑测试** | `node tools/verify.mjs --quick`（32 秒）/ `node tools/test-all.mjs`（约 8 分钟） |
| **跑单条攻击的单测** | 每个攻击面基本都有对应套件，见 §4 |
| **写 PoC 代码**（不进主干） | 放你自己的分支/临时文件，**不要提交到 main** |

| **不能做** | 原因 |
|---|---|
| 真机攻击（连真 QQ） | 没有 profile、没有 QQ 号 |
| 改 `lib/` 里的实现 | 你要出的是**报告**，不是补丁 |
| 把仓库内容外传 | 里面仍有公开但**不宜扩散**的东西（见 `PRIVACY.md`） |
| 对真人做社会工程 | 那是伦理问题不是技术问题 |

**注意**：正因为你**没有真机**，所以「动态攻击」打不了 —— 但这不等于打得少。
这个项目的历史上，**最有价值的发现全部来自静态审计**（见 `REDTEAM.md` §10 引的那句话）。

## 5. 交什么（格式严格）

每条发现一条记录，**必须六项齐全，缺一项不收**：

```markdown
### [编号] 一句话标题

- **位置**：`lib/xxx.js:123`（必须能点到行）
- **前提**：攻击者需要什么（P1 浏览器 / P2 能发消息 / P3 能注入内容 / P4 本机进程 / P5 能改代码或提 PR）
- **手法**：具体做什么（越具体越好，能复现的步骤）
- **成功判据**：**怎么算打穿了**（客观、可验证；不要写"可能造成"）
- **现防线**：代码里有没有对应的检查（有就指出位置；没有就写"无"）
- **为什么没被 G 表收录**：一句话说明它和已知缺口的区别
```

**判据必须客观。** 反例：「可能导致信息泄露」——不收。
正例：「`qq-events.jsonl` 里出现该字符串」/「该请求在 attacker 侧访问日志中出现」。

**不要写的**：

- 泛泛的「建议加强输入校验」—— 没有具体位置和判据的，不收
- 已知缺口（见 §4）
- 代码风格、性能、可读性问题（这不是目标）

## 6. 三条禁令

1. **不改主干**：不要 commit 到 `main`，不要开 PR 改实现。要写 PoC 就放临时文件或你自己的分支。
2. **不外传**：仓库虽然公开，但**不要**把内容贴到第三方平台、不要喂给别的模型做训练。
3. **不碰真实数据**：`dataRoot` 里的会话、图片、事件流都是真人的，**不要读、不要传**。
